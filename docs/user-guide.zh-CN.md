# MoonGuard 1.0 使用手册

月盾把一组文件变更分成三个步骤：先预演、检查后执行、需要时检查并恢复。适合小型文档目录的批量整理，也能审核外部工具提出的操作。

## 安装与启动

从本项目 GitHub Releases 下载 `MoonGuard-1.0.0.zip` 并完整解压。安装 Node.js 22 或更新版本后，Windows 双击 `Start-MoonGuard.cmd`；Linux 使用 `sh start-moonguard.sh`。macOS 提供相同脚本但尚未实机验证。普通使用无需安装 npm 包，无需 MoonBit 编译器，无需模型密钥。

启动器选择空闲端口，显示 `http://127.0.0.1:端口` 并尝试打开默认浏览器。如果没有自动打开，复制地址手动打开。保持终端窗口运行，按 Ctrl+C 停止服务；它会等待当前请求完成。关闭网页本身不会停止服务。

这是在每位用户自己电脑上运行的工具，本机地址不能发给别人当作在线服务访问。

## 第一次使用

1. 默认打开一份隔离示例，可先熟悉“生成预演 → 确认并执行 → 恢复上一次操作”。
2. 点击“打开资料目录”，从文件管理器地址栏复制文件夹的完整路径，例如 `D:\Documents\我的知识库`。首次使用选资料副本。
3. 确认左侧显示你选择的路径。展开“支持范围与未参与处理的项目”，检查哪些项目没有进入文件列表。
4. 点击“新建操作”，选类型、填路径、加入计划，可重复添加多个操作。
5. 点击“预演这份计划”，逐个查看执行前后的路径与内容。确认后执行。
6. 在“恢复记录”查看这次事务；“检查并恢复”会先验证文件没有被其他应用改动。

主分支新增恢复预演窗口（旧版 v1.0.0 下载包尚未包含）：点击恢复后，先展开路径查看“当前内容”和“恢复结果”，确认无误再点击“确认恢复”。关闭窗口可取消，存在冲突时确认按钮不可用。若查看后文件又被修改，恢复会停止，需关闭窗口后重新预演。较大内容在窗口中截取前 8000 个字符，完整计划可通过 CLI `restore-preview` 查看。CLI `restore` 和未提供 reviewId 的旧 HTTP 调用仍直接执行经过检查的恢复。

有未恢复的中断事务时，先恢复再创建新计划或切换目录。切换目录会清除未执行计划，但不会清除原目录的恢复日志。重新打开原目录即可查看历史。

## 四种操作

| 操作 | 填写方式 | 结果 |
| --- | --- | --- |
| 移动 / 重命名 | 原路径与目标路径，如 `notes.md` → `archive/notes.md` | 目标必须不存在；不自动更新文档链接 |
| 新建文件 | 路径和完整内容 | 支持新建子目录下的文件；拒绝覆盖已有文件 |
| 修改内容 | 选择已有路径，点击“读取当前文件内容”后编辑 | 完整替换该文件内容，必须检查预演 |
| 回收文件 | 已有文件路径 | 内容保存在月盾恢复日志，未进入系统回收站 |

路径相对于当前资料目录，子目录用 `/` 分隔。列表中的操作按添加顺序执行。可移除不需要的操作；所有路径与冲突判断由预演再次检查。

“按主题归档”是独立的规则功能：根目录 `.md` 文档使用 `category: engineering`、`category: product` 或 `category: research` 时，可归档至相应分类并调整受支持的简单 Markdown 行内相对链接。没有对应标记时可能没有变化；这不代表已经整理了整个知识库。它不支持完整 Markdown、Obsidian 双链或任意 YAML 结构。

## 支持范围

- UTF-8 文本：`.md`、`.txt`、`.json`、`.csv`。
- 最多 200 个文本文件、200 项操作；单文件 262,144 个 UTF-16 码元，总计 2,097,152 个码元。
- 扫描最多 1,000 项。隐藏项、链接文件、二进制、过大文件不会参与操作。
- 仅协调单一工作区中的月盾写入。执行或恢复时暂停编辑器自动保存、云同步和其他程序写入。
- 恢复针对路径和文本字节内容，不包括文件时间、ACL 等元数据。不是全盘备份，也不提供跨文件原子事务或断电保证。

## 常见问题

**打不开页面：** 查看启动窗口是否仍在运行，使用窗口打印的地址。手动启动可用 `npm start -- --port 0 --open` 自动选择端口。

**目录打不开：** 输入完整路径，确认目录存在且当前用户有读取和写入权限。不要选择链接目录、整个磁盘或超大资料库。月盾会在资料目录内创建 `.moonguard` 保存恢复日志。

**预演过期：** 文件在预演后被更改，月盾拒绝执行。检查新增修改，再重新预演；不要删除人工修改来强行通过。

**恢复出现冲突：** 保存当前文件和 `.moonguard` 的副本，核对提示路径。系统不会直接覆盖冲突内容。需要手工合并时，先保留所有版本。

**进程被强行结束后提示锁：** 参照 README“中断恢复与日志”，确认没有其他月盾进程写入再处理过期锁，不要直接删掉整个 `.moonguard`。

**升级：** 停止旧服务，将新版解压至新目录，再打开原资料目录。恢复记录位于资料目录；请保留原目录与 `.moonguard`。1.0 延续现有日志 schema 1；不会自动迁移、清理旧数据。降级前保留副本。

## 隐私、MCP 与反馈

独立工作台不上传文件内容，没有自动遥测。恢复日志和导出计划包含文件内容且未加密，应按原资料的敏感程度保管。

MCP 为可选集成，需要单独安装依赖。外部客户端读取文件时，内容可能交给其模型服务商。MCP 会话的目录由启动配置固定，页面不能扩大它；更换目录请修改启动配置并重启。详见 `integrations/mcp/README.md`。

“参与试用（可选）”不影响日常功能，可跳过。记录由本人主动导出和交付；演练与真实试用分开汇总。

向 GitHub Issues 反馈版本、操作系统、操作步骤、预期与实际结果；使用虚构文件提供复现，不要上传真实日志、完整计划或私密文档。
