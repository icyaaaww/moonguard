# 月盾：三分钟现场演示

## 上台前

在项目根目录运行 `npm start`，打开本地页面。使用默认的隔离示例工作区，关闭其他正在演示该工作区的窗口。点击“新建示例工作区”。所有演示内容均为虚构资料，没有真实用户信息。

不用准备模型 API 密钥，也不依赖在线模型结果。明确说明：此演示使用可重复的规则规划器；外部 AI 可以通过操作 JSON 接入，但本版尚未集成大模型。

## 0:00–0:25 问题

“我愿意让 AI 帮我整理资料，但不愿意点完运行之后，才知道它改了什么。更麻烦的是，运行到一半出错，或者我已经补写了内容，再点撤销可能造成第二次损失。月盾把文件任务变成一份能检查、能校验、能恢复的计划。”

指向当前文件树：四篇文档混在根目录，README 用相对链接引用它们。

## 0:25–1:00 预演

点击“生成预演”，展示 README 的 before/after。点击“预演之后”，展示工程、产品和研究目录；选择 architecture.md 展示移动后的相对链接。

“原文件还没有改变。我们先算出最终影响；同一份 MoonBit 核心同时运行在浏览器和执行端，规则不会各写一套。”

## 1:00–1:35 保护人工修改

点击“模拟用户修改”，再点“确认并执行”，等待红色提示 README 已在预演后变化。

“我刚刚在另一个编辑器里加了一段文字。月盾发现计划过期，拒绝写入。重新预演才会把我的新内容纳入计划。”

点击“生成预演”，然后“确认并执行”；展示归档后的文件。点击“恢复上一次操作”，看到路径恢复、人工段落仍存在。

## 1:35–2:20 故意中断

点击“新建示例工作区” → “生成预演” → “在第 2 步后中断”。

“这不是播放动画。执行器已修改了两项净路径变化，然后主动抛出异常。你现在看到的是一个不完整的真实文件状态。修改之前保存的日志，让我们有依据恢复。”

点击“恢复中断的事务”，等待“恢复完成”；打开“恢复记录”。不要将可控异常注入称作物理断电实验。

## 2:20–3:00 复用价值

“这次整理知识库只是一个入口。任何规划器都可以提交创建、写入、移动和回收的操作 JSON。MoonBit 库负责计划和冲突，宿主负责真实文件和日志。我们希望给 MoonBit 的 Agent 工具提供一个可以直接复用的文件操作基础。”

展示公共 API、测试结果和仓库结构。根据实际状态说明是否已发布 Mooncakes、是否已取得真实用户反馈；没有完成就明确说还在下一阶段。

## 评委可能追问

**为什么不直接用 Git？** Git 对代码历史非常有价值。月盾关注每次工具调用前的操作语义、文件路径约束、快照失效与恢复冲突；适合不一定建立 Git 仓库的文档目录，也可与 Git 结合。不要声称 Git 做不到差异或恢复。

**是不是包装了一个 JSON 页面？** 展示 MoonBit 的 `plan/check_apply/restore_plan`、真实执行日志和自动故障恢复测试。Node 承担 I/O，核心决定是否允许执行。

**是不是完全安全？** 当前是受限文本操作和协作式工作区，不能抵御本机恶意进程竞态，不能执行任意 shell，也没有证明断电原子性。

**AI 在哪里？** 当前集成点是外部操作 JSON，示例规划器是规则式。实际模型/OpenSeek 适配属于下一阶段，不能假装已经完成。

**恢复遇到人工冲突怎么办？** 整个恢复先停止并保留现状，让用户检查冲突。没有自动覆盖或未经确认的自动合并。
