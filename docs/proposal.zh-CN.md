# MoonGuard 月盾：让 AI 的文件操作可预演、可检查、可恢复

版本：0.1.0 原型；2026 年 10 月 13 日。参赛者：icyaaaww；仓库：https://github.com/icyaaaww/moonguard 。正式 Mooncakes 包名待注册确认。提交用申报书见 [application.zh-CN.md](application.zh-CN.md)。

## 项目摘要

AI 能迅速改写和整理资料，但用户往往只能在执行后发现问题：文件被搬错位置、链接失效、执行到一半中断，或者恢复时覆盖了自己的新修改。月盾把一次文件任务转化为可以检查的操作计划：先展示影响范围和内容差异，执行前检查计划是否过期，修改前保存恢复资料，恢复前再次检查是否存在人工改动。

交付形式是 **MoonBit 核心库 + 本地执行适配器 + 可交互演示工作台**。首个场景聚焦小型 Markdown 知识库整理。选择这个场景，是因为评委可以直接看到“文件树变化、链接跟随更新、出错后恢复”，同时核心协议能被其他 AI 文件工具复用。

一句话路演：**“AI 提议怎么改，月盾先让你看见；执行出了问题，也能检查着恢复。”**

## 服务谁，解决什么

第一批目标用户是用 AI 整理文档的个人开发者、维护项目知识库的小团队，以及正在给 Agent 增加文件操作能力的 MoonBit 开发者。这是目标用户假设，尚未完成真实访谈或需求验证。

| 具体时刻 | 用户遇到的问题 | 月盾提供的行为 |
| --- | --- | --- |
| AI 提交一串移动和修改 | 不知道会改哪些文件 | 文件树与逐行对照，确认影响范围 |
| 预演后用户又编辑了资料 | 旧计划可能覆盖新内容 | 执行前重读快照，拒绝过期计划 |
| 任务执行到一半异常 | 工作区处于混合状态 | 保存原始内容，提供中断恢复 |
| 执行后用户又修改文件 | 直接撤销可能丢掉新劳动 | 恢复前逐路径检查，冲突时停下 |
| 工具作者换了模型供应商 | 安全逻辑和模型实现耦合 | 用统一操作 JSON 接入核心库 |

## 现场最有说服力的一幕

先把四份混放文档按主题归档，展示 README 和文档之间的相对链接同步调整。接着故意制造故障，让执行停在第二个净路径变更后，现场打开文件视图，展示不完整状态，再点击恢复。

第二个场景更能体现区别：预演之后点击“模拟用户修改”，再执行旧计划。月盾明确指出 README 已变，拒绝执行；重新预演后，人工新增段落被保留。

用这些可复现行为证明工程质量。不要用预录结果伪装实时执行，也不要把异常注入表述成已经通过断电可靠性验证。

## 为什么 MoonBit 在这里是核心

计划的数据模型、路径政策、冲突检测、净变更计算、恢复计划、JSON 协议和示例规划器由 MoonBit 实现。Node 只负责文件系统、日志和本机 HTTP，浏览器代码负责交互展示。

MoonBit 核心编译出的同一个 JS 模块同时用于浏览器与执行器：预演和执行校验共享语义。公共 API 独立于模型和界面，可以作为 Mooncakes 库集成。核心测试还可在 Wasm GC 上运行，为未来其他宿主留下空间。

参赛材料应分别列出 MoonBit 源文件、宿主适配层和生成代码；不要把生成的 JS 行数当作手写贡献，也不要声称整个应用都由 MoonBit 编写。

## 与已有方向的关系

已调研 MoonBit 的 OpenSeek、workflow，以及 moonundo、moontxnkit 等相关项目。它们让 Agent 工具、流程恢复、状态撤销或事务机制具备不同程度的基础。月盾的候选差异点是：**围绕真实本地文件影响，把用户可理解的预演、过期检查、恢复冲突检查和可复现故障演示连成闭环。**

这属于产品与工程组合上的差异，不应宣称首创撤销、事务或日志恢复。与现有项目的 API 接入、性能和行为逐项对比仍需在正式提交前补充；目前没有测得的竞品优劣数据。

后续优先选择 OpenSeek 做一个真实文件工具适配示例：规划器输出结构化操作；预演后由用户确认；执行器只接受已验证计划。是否集成、如何集成应根据其当时接口验证，不能在本版材料里写成已经完成。

## 面向高奖项的投入顺序

第一优先级是让陌生开发者仅看 README 就能跑通，并提供一个真实项目的使用证据。邀请 3–5 位目标用户完成“查看预演、识别风险、执行、恢复”任务，记录完成率、误解点、失败原因和授权后的反馈；这些数值目前没有采集。

第二优先级是证明库有复用价值：完成一个外部工具适配，把协议示例整理成可直接运行的包使用示例。重点展示业务规则与文件宿主分离的价值。

第三优先级才是增加模型能力和视觉演出。大模型应提出操作，不能绕开计划验证直接执行任意命令。避免把时间分散到聊天框、插件市场、多种模型配置和复杂账户系统。

建议量化的验证：有效计划通过率、过期计划拦截、每个故障位置的恢复结果、人工改动保护，以及不同规模工作区的预演耗时和内存。必须发布输入规模、机器环境、原始结果与失败案例，不能填入未经测量的性能数字。

## 需要如实说明的边界

月盾 0.1 面向协作式、小型文本工作区。它没有通用 shell 沙箱、云 API 补偿事务、任意文件格式支持或断电级事务保证。Markdown 规则是受限示例；文件恢复主要针对路径和文本内容。详见架构文档。

这一边界不是路演中一带而过的小字：评委如果问“后台同步在你检查后又写了怎么办”，应直接回答当前仍存在文件系统检查与写入间的竞争窗口，演示要求暂停外部写入，下一步会研究更强的宿主隔离与平台专用原子操作。
